In Micronaut development mode, a restart of the application keeps the R2DBC `ConnectionFactory` of each configured data source: the next application context is served the same instance, so an `r2dbc:pool:` connection pool keeps its open connections, and an in-memory database survives the restart. A change of the configuration under `r2dbc.datasources` releases the connection factories, and the next application context creates them again from the changed configuration. Outside development mode nothing changes.

NOTE: Known issue: a released connection factory is not closed. Micronaut R2DBC does not close a connection factory when the application context stops, in development mode or not, so a pool released by a configuration change keeps its open connections until they are evicted or the process exits.
